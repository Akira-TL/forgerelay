# Domain Docs

ForgeRelay uses a single domain context.

Before feature or architecture work, read `CONTEXT.md` when it exists and any
relevant ADR under `docs/adr/`. These documents define domain vocabulary and
hard-to-reverse architectural decisions; implementation details still belong in
code, tests, and feature documentation.

Use the glossary vocabulary consistently in issue titles, tests, schemas,
errors, and documentation. If a proposed change conflicts with an ADR, surface
that conflict explicitly before overriding the decision.
