# ForgeRelay 1.2.3

ForgeRelay 1.2.3 是一个 Activity Panel / debug 一致性补丁版本。它修复 ChatGPT sandbox iframe 加载 MCP App 静态资源时被全局 Origin validation 提前拒绝的问题，并让交互式 `7677` debug 实例使用与生产一致的 ForgeRelay Skill source。

## 修复

- MCP App 静态资源路由现在位于 API Origin validation 之前。ChatGPT 的 `*.web-sandbox.oaiusercontent.com` iframe 可以正常获取 `/mcp-app-assets/*` JavaScript/CSS，并继续收到 `Access-Control-Allow-Origin: *` 与 `Cross-Origin-Resource-Policy: cross-origin`。
- 这一调整只适用于公开的 MCP App 静态资源。MCP、OAuth、health 之外受保护的 API 路由仍经过现有 Origin validation；同一个 ChatGPT sandbox Origin 对 MCP 请求仍返回 `403`，不会因为 UI 资源兼容性而扩大 API 信任边界。
- 交互式 `npm run dev` / `7677` debug 运行时现在复用生产 ForgeRelay 的 Skill source（默认 `~/.forgerelay/skills`），但继续使用独立的 debug config、auth、state 与端口。这样 Workspace / Activity Panel 中的 Skill 展示与生产发现语义一致，而调试运行态仍保持隔离。

## 回归确认

- `src/mcp/server/transport/http-origin.test.ts` 覆盖 ChatGPT sandbox Origin：MCP App asset 请求成功，MCP API 请求仍被拒绝。
- 真实 `https://babelbeast.com/forgerelay/debug/mcp-app-assets/...` 路径已验证能够向 ChatGPT sandbox Origin 返回 JavaScript 资源。
- `scripts/debug/runtime.test.mjs` 覆盖 debug Skill source 与生产 source 的对齐行为。
- 先前在 v1.2.1 修复的 Relay Workspace Panel stateless reconstruction 未回归：Panel 定向测试通过，Relay routing 定向测试通过，真实 `7677` Gateway → `7678` Execution acceptance 中 `open_workspace` 后跨 stateless MCP request 的 `activity_panel` 明确通过。
