# ForgeRelay 1.2.5

ForgeRelay 1.2.5 是 1.2 系列 Config System v2 的收尾补丁版本。它不扩展新的配置域，而是把持久化形状、端口约束、初始化写入与迁移失败边界统一到同一套 Config v2 contract，为后续 1.3 的 CLI 与 Agent context 配置工作冻结一个稳定基线。

## Config 持久化

- `config.json` 的写入路径现在会在落盘前通过 Config v2 schema 校验，避免 CLI 或 setup 写出运行时随后拒绝的非法配置。
- 初始化只持久化用户真正选择的 override。HTTPS proxy 场景不再重复写入可从 loopback bind 与 public URL 安全推导的 `trustedProxies: ["loopback"]`。
- 用户显式写下的值仍然保留，即使它恰好等于 built-in 或当前派生结果；ForgeRelay 不会把“显式 override”误当成“冗余默认值”删除。
- 文档明确了网络字段的权威关系：`host` / `port` 控制本地 bind，`publicBaseUrl` 声明 client-facing endpoint；`allowedHosts` 与 `trustedProxies` 只有在没有显式 override 时才允许派生。

## Port validation

- ForgeRelay 主监听端口的支持范围统一为 `1`–`65535`。
- JSON Schema、环境变量、`init --advanced`、持久化 writer、migration 与 runtime resolver 使用一致的边界约束。
- External MCP OAuth `callbackPort` 保持独立的 `1024`–`65535` contract，没有因为本次统一而放宽到低位端口。

## Migration

- `forgerelay config migrate` 在准备写回 General Config 前验证 canonical Config v2 shape。
- 如果 legacy source 中存在非法 General Config，例如超出范围的 `port`，migration 会在创建 canonical target、backup 或修改原文件之前失败，避免留下部分迁移状态。
- v1.2 的 legacy compatibility window 保持不变；本版本不提前删除任何计划在后续版本移除的 parser/path。
