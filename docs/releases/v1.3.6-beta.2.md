# ForgeRelay 1.3.6-beta.2

本次 beta 修复 `1.3.6-beta.1` 在 npm 全新安装或更新后，文件修改后的语言服务初始化错误可能使 ForgeRelay 主进程退出的问题。已发布的 `1.3.6-beta.1` 包含该故障，应使用本版本替代。

## 修复内容

通信连接、协议请求类型和取消令牌现在统一从 `vscode-languageserver-protocol` 取得，移除 ForgeRelay 对 `vscode-jsonrpc` 的直接依赖。这样即使 npm 为其他组件安装另一份通信库，语言服务也不会混用不同模块中的参数标记。该问题在实际安装组合 `vscode-jsonrpc 9.0.3` 与协议包内部的 `10.0.0` 中得到复现。

初始化请求同步抛错也会执行退出监听器清理，避免 ForgeRelay 随后关闭子进程时，遗留监听器再产生未处理的 Promise 拒绝。文件写入成功后，诊断失败继续以有界警告返回，不撤销已保存的文件，也不通过吞掉全局异常维持运行。

## 故障日志和升级

保留上一 beta 引入的 `<stateDir>/logs/runtime.jsonl` 持久故障日志、权限限制及轮换行为。本次故障正是通过日志中的初始化失败、信号发送位置和未处理拒绝顺序定位。无需配置迁移；更新包后需由用户按原有方式重新启动相应实例，已运行的旧进程不会自动载入修复。

## 验证范围

旧安装包在隔离子进程中复现了原始初始化期间 `SIGTERM` 和主进程退出。修复构建在隔离副本中复用同一实际故障依赖树，完成初始化及诊断且主进程存活。新增回归同时覆盖两份真实通信库模块，以及真实 MCP 文件写入后的同步初始化异常、文件保留和后续恢复；Node.js 22 与 26 下均已验证。

本次按开发者明确指定，仅使用开发实例完成操作验收，免除本版本的开发者手动验收；发布前仍需通过 ForgeRelay-dev 对全新安装候选包的操作验收、最终提交的完整本地发布门禁、隔离打包验收和标签触发的云端检查。

本次证据解释已复现的 beta 初始化故障，不代表更早版本的每次退出都具有同一依赖组合。

## 发布通道

包版本为 `@akira-tl/forgerelay@1.3.6-beta.2`，Git 标签为 `v1.3.6-beta.2`，npm 分发标签为 `next`，GitHub 标记为预发布；不提升 npm `latest`。本版本发布不更改任何运行中的实例或部署配置。
