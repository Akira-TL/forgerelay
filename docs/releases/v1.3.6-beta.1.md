# ForgeRelay 1.3.6-beta.1

本次 beta 针对文件修改后自动语言服务诊断失败的问题，修复已被确定性测试证实的服务清理竞态，并增加重启后仍可读取的故障日志。它用于验证稳定性，不代表历史事故中的所有退出路径均已查明。

## 服务生命周期修复

清理任务在等待前一个服务关闭后，会重新检查下一个服务是否仍归当前管理器所有、是否仍为空闲、最近使用时间是否仍满足回收条件。并发的 `write` 或 `edit` 重新使用服务后，旧清理名单不再直接关闭该服务。

配置变更触发的服务回收也重新检查活动状态。服务器整体关闭时，先等待已开始的语言服务操作结束，再关闭子进程。

## 持久化故障日志

启动时显示日志路径：`<stateDir>/logs/runtime.jsonl`。同目录下的 `.1`、`.2`、`.3` 文件为较旧日志，每个文件最多 4 MiB，总计最多约 16 MiB；重启后保留。新文件仅允许当前用户读写。

日志包含时间、ForgeRelay 进程编号、版本、语言服务实例标识、项目根目录、子进程编号、活动请求数、启动与退出事件、关闭原因，以及 ForgeRelay 发送 `SIGTERM` 时的调用栈。未捕获异常保留异常类型、错误码、调用栈和退出码，Node.js 仍按原有规则退出，不将异常吞掉后继续运行。

日志不保存源码、请求正文、完整环境变量、语言服务器标准错误输出或任意异常消息。日志包含本机路径，分享前应检查这些路径。`SIGKILL`、断电等无法执行进程回调的情况不能依赖退出事件捕捉。

## 验证与未决问题

候选实现已通过清理竞态回归、真实 Pyright 的隔离 HTTP/MCP 文件修改验证，以及持久日志的轮换、权限、写入失败和未处理 Promise 拒绝退出测试。正式发布前仍须完成最终提交的完整发布门禁、打包验收和开发者实际操作验收。

历史终端记录确认 1.3.5 与 1.3.4 均曾出现语言服务器初始化期间收到 `SIGTERM`，随后 Node.js 退出。记录未包含信号发送者；目前已证实并修复的清理竞态尚不能单独证明这条完整退出链路的根因。发现新故障时，请保留该实例的上述日志文件。
