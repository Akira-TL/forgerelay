# ForgeRelay 1.3.5

ForgeRelay 1.3.5 修复 OAuth 动态客户端注册（Dynamic Client Registration, DCR）对已知 MCP Host 域名的隐式依赖，使 Gemini Connected Apps 等标准 OAuth/MCP 客户端无需 ForgeRelay 预先内置厂商 redirect host 即可完成注册。

## 修复：开放标准 HTTPS DCR callback

此前 ForgeRelay 默认只允许 `chatgpt.com`、`localhost` 与 `127.0.0.1` 作为 OAuth redirect host。对于 Gemini Connected Apps 使用的 `https://oauth-redirect.googleusercontent.com/r/...` callback，客户端注册会被拒绝；若手动把 `chatgpt.com` 当作 `client_id` 传给 `/authorize`，ForgeRelay 又会正确返回 `invalid_client`，因为该值并不是已注册客户端。

1.3.5 将默认策略改为协议约束而不是厂商名单：

- 动态注册默认接受任意有效 HTTPS redirect URI；
- localhost、127.0.0.1 与 ::1 继续允许 HTTP/HTTPS loopback redirect；
- 非 loopback 的明文 HTTP 与自定义 URI scheme 继续拒绝；
- `FORGERELAY_OAUTH_ALLOWED_REDIRECT_HOSTS` 保留为可选 operator restriction；配置为非空时，会把非 loopback HTTPS callback 收紧到该名单；
- DCR 仍由 ForgeRelay 的 `/register` 端点签发 `forgerelay-<uuid>` client ID，不接受任意未注册 `client_id`。

## 安全边界保持不变

本补丁没有放宽 OAuth 的核心授权约束：

- `/authorize` 仍要求 `client_id` 已注册；
- 请求中的 redirect URI 仍必须与该 client 注册的 URI 精确匹配（loopback 仅保留既有端口兼容语义）；
- PKCE S256 仍为强制要求；
- Owner OAuth、resource validation、token/refresh/revocation 逻辑保持不变；
- OAuth client 与 token 状态继续持久化在 ForgeRelay 自己的受保护 state store 中。

## 兼容性

- ChatGPT 现有 OAuth 流程保持兼容；
- Gemini Connected Apps 等使用 HTTPS callback 的标准 MCP Host 不再需要 ForgeRelay 增加 vendor-specific redirect allowlist；
- 已显式配置 `FORGERELAY_OAUTH_ALLOWED_REDIRECT_HOSTS` 的部署继续保持原来的严格 host 限制；
- 该变量是 redirect host allowlist，不是合法 `client_id` 列表。

## 验证

回归覆盖：

- Gemini 风格 `oauth-redirect.googleusercontent.com/r/...` 的真实 HTTP DCR `/register` 路径；
- 任意 HTTPS callback；
- localhost、127.0.0.1 与 ::1 loopback callback；
- 非 loopback HTTP / custom scheme 拒绝；
- 显式 redirect-host allowlist 的限制语义；
- 未知 `client_id` 与未注册 redirect URI 继续拒绝；
- OAuth config 与 TypeScript 类型检查。

正式发布继续使用 ForgeRelay 既有 release gate、Node 22.19.0 parity、packaged acceptance、release proof 与 tag 驱动的 Linux/macOS/Windows 云端发布流程。
