# ForgeRelay 1.3.4

ForgeRelay 1.3.4 增加长时间开发会话的确定性老化提示，让 Host 可以在合适的边界把项目连续性重新交给持久 Workspace，而不是无限依赖旧对话上下文。

## 新增：Workspace 对话健康建议

新增低频、只读的 `workspace.conversation-health` Capability。它只使用 ForgeRelay 能真实观察到的状态，不估算 Host token 数、上下文窗口利用率、模型记忆压力或内部推理状态。

当前策略固定为：

- 当前对话作用域与 Workspace 累积 12 个 Host Turn 时，如果没有近期持久 checkpoint，返回 `checkpoint-recommended`。
- 累积 24 个 Host Turn 时返回 `rotation-recommended`。
- checkpoint 创建后的 8 个 Host Turn 内视为近期恢复边界；超过该窗口后，轮换建议会先要求建立新 checkpoint。
- 所有建议都只提供指导，不会自动创建 checkpoint、结束 Host 对话或强制轮换。

## 有界交接与恢复

对话健康结果可以同时返回有界的持久状态摘要：

- 最多 20 个未完成 Workspace Task 的头部信息，不包含 Task 正文；
- 最新持久 Workspace checkpoint 的有界元数据，不包含 patch 或文件正文；
- Git-backed Workspace 的 HEAD、分支、dirty 状态和变更文件数量。

新 Host 对话重新 `open_workspace` 后，可以继续从相同 Workspace identity、Task、checkpoint 和 Git 状态恢复工作，不需要复制旧对话全文或长篇 prose handoff。

Workspace Relay 会在拥有真实 Workspace 的 Execution ForgeRelay 上执行同样判断。Composite Workspace 需要显式指定 member：对话年龄继续取顶层 Composite Host Turn，checkpoint、Task 与 Git 状态取该 member 的执行 Workspace。

## 兼容性

- 不新增 Core MCP tool；新功能通过现有 Capability Gateway 暴露。
- 不新增数据库表，也不需要 Config System v2 迁移。
- 不改变 `workspace.checkpoint` 的显式 mutation 语义。
- 不保存完整 Host conversation transcript。
- 现有 Workspace、Activity、Task、checkpoint、Relay 与 Composite 生命周期保持兼容。

## 验证

实现回归覆盖 11→12、23→24，以及 checkpoint 近期窗口 8→9 的精确边界；同时覆盖 conversation A 建立 checkpoint 后由
conversation B 打开同一 Workspace 并恢复 Task/checkpoint/Git 真相的真实公共 MCP 路径。

受影响的 `workspace-state`、`workspace-relay` 与 `mcp-server-ui` CI shards 已通过，TypeScript 类型检查、架构检查、生产构建与公共 Capability contract 定向测试也已通过。

正式发布继续使用仓库既有 release parity、打包验收、release proof、release-ready push 和 tag 驱动的跨平台云端 CI / npm / GitHub Release 流程。
