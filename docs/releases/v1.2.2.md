# ForgeRelay 1.2.2

ForgeRelay 1.2.2 是一个面向 routed public URL 的小修复版本，重点修复带路径前缀的公网部署在 MCP Origin 校验、OAuth callback 和 MCP App CSP 上的兼容性问题。ForgeRelay 1.2 的配置与执行模型保持不变。

## 修复

- `publicBaseUrl` 的 canonical hostname 现在会进入 MCP transport 的允许 Origin 集合。合法的同源浏览器请求可以继续进入 OAuth，而 foreign Origin、非法 Origin syntax 和无 Origin 的 native MCP client 仍按原安全边界处理。
- OAuth authorization callback 现在包含 metadata 中公布的 issuer (`iss`)，保持 routed authorization server URL 与 callback 结果一致。
- MCP App 的 CSP `resourceDomains` 和 `connectDomains` 现在使用 URL Origin，而不是带部署路径的完整 `publicBaseUrl`。这修复了类似 `https://example.com/forgerelay/main` 的部署中 HTML 已加载但 JavaScript/CSS 被 Host CSP 阻止、面板停留在 `Waiting for Activity Panel state.` 的问题。
- Skill 默认发现范围收敛为 Project `.agents/skills`、Project `.forgerelay/skills` 与 active ForgeRelay config `skills`（默认 `~/.forgerelay/skills`）。ForgeRelay 不再自动扫描全局 `~/.agents/skills` 或 `FORGERELAY_AGENT_DIR/skills`；`FORGERELAY_SKILL_PATHS` 仍保留为用户显式附加来源。

## 安全边界

- Origin validation 没有被关闭，也没有使用 `*`、删除 Origin header 或由反向代理伪造 trusted Origin。
- `allowedHosts` 与 Origin allowlist 继续保持不同语义；只有 canonical public URL 的 hostname 会自然同时参与两者。
- path prefix 不参与 Origin identity，显式 port 则由 URL Origin / transport contract 按各自语义保留。

## 验证

- routed public Origin regression：同源请求进入 OAuth `401`，foreign Origin 保持 `403`，无 Origin 与 malformed Origin 行为保持不变。
- MCP App path-prefix regression：CSP metadata 使用 Origin，真实 `7677` 隔离实例中的 `/forgerelay/main/mcp-app-assets/...` JavaScript 资源返回 `200`。
- focused server / OAuth / Panel tests、TypeScript typecheck、architecture check、core contract 与 release gate 按发布流程执行。
