# ForgeRelay 1.1.1

ForgeRelay 1.1.1 makes External MCP a practical long-running configuration surface: servers can be added or changed without restarting ForgeRelay, human OAuth authorization is handled from the CLI, and the MCP runtime is updated for current 2026 protocol interoperability without dropping the existing legacy paths.

## External MCP configuration

- External MCP servers now use standalone `mcp.json` registries. Machine-wide configuration lives in the ForgeRelay config directory and a Workspace may provide `<workspace>/.forgerelay/mcp.json`.
- Effective server configuration is resolved as Project → global → legacy `config.json.mcpServers`. Project entries may explicitly mask inherited servers with `disabled: true`; removing the Project entry exposes the lower-precedence definition again.
- Valid configuration changes are hot-loaded for the next External MCP operation. Each operation keeps one immutable snapshot, and an invalid live edit keeps the whole previous valid source as last-known-good rather than activating a partial registry.
- `mcp.external` remains discoverable even when no server is configured yet, so the first hot-added server does not require a Host reconnect.

## External MCP authentication and CLI

- `forgerelay mcp auth <server>` performs explicit human OAuth authorization with PKCE. Desktop flows use a short-lived loopback callback; SSH/headless flows print the authorization URL and accept the final callback URL with masked `*` input.
- OAuth state is stored in machine-private `mcp-auth.json`. Project credentials are keyed to the Project root and do not silently carry across Projects when configuration is copied.
- The running ForgeRelay process only consumes and refreshes stored credentials. Normal refresh is non-interactive and coordinated across ForgeRelay processes; fresh consent, changed authorization binding, or scope step-up returns an actionable reauthorization requirement instead of opening a browser from runtime execution.
- Dynamic Client Registration remains supported for compatible authorization servers. CIMD-only servers can opt into an operator-provided public `clientMetadataUrl` plus its exact loopback `callbackPort`; ForgeRelay does not require or provide a hosted CIMD service.
- `forgerelay mcp logout <server>` removes the local credential even when remote revocation is unsupported or fails.
- `forgerelay mcp list` reports effective global/Project/legacy source, disabled state, authentication state, credential-store health, and invalid/last-known-good configuration. `forgerelay mcp test <server>` performs the active connection and tool-discovery probe. `forgerelay doctor` remains passive and never starts configured stdio MCP servers or makes HTTP MCP requests.

## MCP 2026 interoperability

- ForgeRelay now uses the split MCP SDK v2 and Apps SDK v2 runtime packages.
- External MCP clients negotiate modern MCP 2026-07-28 when available and retain legacy interoperability, including existing stdio and Streamable HTTP servers.
- Host-facing HTTP supports the modern stateless MCP path alongside the existing legacy sessionful path.
- A modern Host Turn uses stable Host conversation metadata when provided. Without stable metadata, modern calls remain request-scoped rather than treating a connection or process lifetime as a conversation. Legacy session/connection compatibility remains bounded to the legacy path.
- Workspace Relay remains compatible with the released legacy Host contract. For relayed Workspaces, External MCP configuration, credentials, refresh, stdio processes, and upstream calls stay owned by the Execution ForgeRelay rather than being copied to the Gateway.

## Security and authority boundaries

- Project stdio MCP entries are executable project configuration and run with the operating-system authority of the user running ForgeRelay; opening an allowed Project is the trust boundary rather than a second per-server approval dialog.
- Static HTTP headers and stdio environment secrets remain user-managed configuration. Project files containing those secrets should not be committed.
- Access tokens, refresh tokens, OAuth client secrets, authorization codes, PKCE verifier state, and pasted callback URLs are excluded from ordinary diagnostic output. Credential files use private atomic storage, and known issuer/resource binding mismatches are rejected before stale bearer credentials are sent.
- External MCP paths, URLs and resource references remain references by default. ForgeRelay does not automatically fetch or read them; explicit `ExternalMcpBeforeForward` / `ExternalMcpAfterForward` Transform Hooks remain the opt-in adaptation seam.
