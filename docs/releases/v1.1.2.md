# ForgeRelay 1.1.2

ForgeRelay 1.1.2 is a small compatibility and discovery patch before the v1.2 configuration-system work begins. It does not introduce Config System v2 behavior.

## Capability discovery

- `open_workspace.capabilityCatalog` is now explicitly documented and described as the callable registry for the `capability` gateway.
- `capabilityFingerprint.capabilities` remains a semantic feature fingerprint, not a list of names that can be passed to `capability(action="describe"|"run")`.
- Capability Guide descriptors remain documentation references rather than callable capabilities. This avoids misleading Agents into calls such as `ui.mcp-app` when that name is present only as a semantic feature capability.

## Agent Skill precedence

- When the same Skill name exists in both Project `.agents/skills` and global `~/.agents/skills`, the Project definition now wins.
- Collision diagnostics continue to report the winning and shadowed Skill sources, so the resolved behavior remains inspectable.

## Compatibility

This release keeps the v1.1 runtime, MCP, External MCP, Workspace, Hook, Language Server, Subagent, and configuration contracts unchanged apart from the fixes above. No Config System v2 migration or new configuration format is introduced in 1.1.2.

## Verification

The release uses ForgeRelay's existing release gate: local/cloud-equivalent verification, package build and acceptance, and the authoritative Linux/macOS/Windows tag-triggered release workflow. The published npm package must be the artifact produced by the verified Cloud CI run.
