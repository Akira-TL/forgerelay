# ForgeRelay 0.9.2

ForgeRelay 0.9.2 完成 0.9 系列的 persistent Workspace checkpoint 阶段：新增低频 `workspace.checkpoint` Capability，让用户和 Agent 可以为稳定 Workspace identity 创建、列出、检查和显式删除持久 Git-visible 工作状态快照，而不改变正常项目历史。

## 主要变化

- `workspace.checkpoint` 支持 `create`、`list`、`inspect`、`delete`；本版本不开放 restore，canonical nine Core MCP tools 保持不变。
- checkpoint 使用独立临时 Git index 创建 immutable snapshot，不移动 branch `HEAD`、不修改 working tree、也不改变真实 staging state；tracked 与非 ignored untracked 内容会进入快照，Git-ignored 文件明确排除。
- checkpoint 归属于 persistent `workspaceId`，可跨 ForgeRelay restart、普通 close/reopen、managed-worktree finalize/backing recreation 与普通 idle GC 保留；只有显式 checkpoint delete 或 Workspace permanent delete 才清理对应 checkpoint state/ref。
- checkpoint lifecycle 与 `review.changes` 的移动 baseline 完全独立；并发 checkpoint mutation 在 Workspace 级串行化，避免多个 conversation 同时操作时丢失持久 identity。
- Relay checkpoint 始终在 owning Execution ForgeRelay 上执行并保存；Composite Workspace 必须显式指定 filesystem member。

## 安全边界

Workspace checkpoints 不是 secrets/config backup。Git-ignored credentials、local config、cache 和其他 ignored files 不会被 checkpoint 捕获。本版本也不会通过 checkpoint 隐式执行 checkout/reset/restore、移动 HEAD、自动提交或修改 ignored files。

## 验证

发布前本地验证覆盖真实 Git working-tree 内容、staging/HEAD 不变性、ignored-file exclusion、并发 mutation、MCP server restart、close/reopen、idle GC、managed-worktree backing recreation、Workspace delete、Relay 与 Composite 路径，并通过完整 `npm test`、build、architecture check、typecheck 与 `git diff --check`。最终发布以 tag 触发的 Linux、macOS、Windows 云端验证为准。
