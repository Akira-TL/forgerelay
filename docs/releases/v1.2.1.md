# ForgeRelay 1.2.1

ForgeRelay 1.2.1 is a focused patch release for Workspace Panel rendering through Workspace Relay. It keeps the ForgeRelay 1.2 configuration and execution model unchanged.

## Fixed

- Relayed Workspaces no longer lose their Activity Panel presentation when `open_workspace` and the later `activity_panel` call are handled by different modern/stateless MCP server instances.
- The Gateway reconstructs the minimum relayed Workspace presentation from durable Relay routing state plus read-only Execution ForgeRelay inspection instead of depending only on per-server in-memory presentation state.
- Composite Workspaces receive the same fresh-server presentation reconstruction, closing the equivalent lifetime gap in their persisted topology.
- Closed relayed and Composite Workspaces remain non-renderable; reconstruction does not reopen or reactivate Workspace lifecycle state.

## Regression coverage

- Relay routing tests now cross a fresh Gateway instance before calling `activity_panel`, and verify that a subsequently closed relayed Workspace remains unavailable from another fresh Gateway instance.
- Activity Panel tests cover Composite presentation reconstruction on a fresh MCP connection and preserve closed-state behavior.
- The real `debug:accept:relay` topology now exercises `open_workspace` followed by `activity_panel` across modern stateless HTTP requests on isolated Gateway `7677` and Execution `7678` instances.
- `src/workspaces/relay/tests/composite.test.ts` is now part of the authoritative `workspace-mcp` CI shard. Its Shell Instructions fixture explicitly opts in, matching the v1.2 default-disabled product contract.
