# ForgeRelay 0.9.4

ForgeRelay 0.9.4 完成 0.9 Workspace Recovery & History 的 P0–P2 收尾：新增 owner-facing retention inspection / explicit prune，并保持默认无限保留、主动工作保护和显式删除边界。

## 主要变化

- `forgerelay maintenance inspect [--json]` 只读报告 Activity/Audit、durable Bash、Host Turn、Workspace/private state、Task、checkpoint 与 review-ref retention 状态，不修改源 SQLite/WAL、Git refs 或 worktrees。
- `forgerelay maintenance prune [--json]` 只执行配置明确授权的 retention 类别；未配置 `historyDays` / orphan administrative cleanup 时为 no-op，不增加后台 scheduler。
- 历史清理以完整 Host Turn cohort 为边界；recent/nonterminal Activity、running Bash 和 active Subagent Run 会保护整个 turn。共享 segmented Activity payload 会先重写保留数据，再删除无引用旧 segment。
- persistent Workspace identity/alias、Task Lists、named checkpoints、non-empty private Workspace state、managed worktrees/branches 与 active runtime state 均不属于 ordinary maintenance prune 删除目标；serve 与 destructive prune 通过 runtime state lease 互斥。
- routed `publicBaseUrl` path prefix 现在也是实际 inbound MCP/OAuth/health/App deployment boundary；setup 区分 loopback HTTPS proxy 与 direct LAN，并用明确 trusted proxy source 代替全局 `trust proxy=true`，修复反向代理 `X-Forwarded-For` 场景。

## 验证

发布前覆盖 no-policy no-op、inspect read-only、eligible/protected mixed retention、Host Turn cohort、running Bash、active Subagent、payload compaction、orphan review refs/private Workspace state、runtime lease 和重复 prune 幂等性。完整 `npm test`、build、typecheck、architecture check 和 `git diff --check` 本地通过；最终发布以 `v0.9.4` tag 触发的 Linux、macOS、Windows 云端验证为准。

## 0.9 P0–P2 收尾

0.9.0–0.9.4 已覆盖 recovery diagnostics、safe managed-worktree recovery、persistent checkpoints、optimistic checkpoint restore 与 explicit retention maintenance。`.worktreeinclude`、native PowerShell/cmd runtime 和 automatic/background maintenance 仍是独立后续工作。
