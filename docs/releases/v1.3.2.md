# ForgeRelay 1.3.2

ForgeRelay 1.3.2 是安全性与稳定性补丁。重点修复 **Activity 查询缺少 Host 对话所有权校验**的问题，并纳入 1.3.1 发布后已经合入主分支的进程等待与面板提示修复。

## 安全修复：隔离不同 Host 对话的 Activity

此前，知道另一段对话 `turnId` 的 MCP App 调用者，可能直接读取该对话的历史 Activity 列表、文件读取结果及 Bash 命令和输出。即使两个对话复用同一个 Workspace，这些历史记录也不应该无条件跨对话可读。

- `activity_snapshot`、`activity_index`、`activity_detail` 和 `activity_output` 在返回内容前检查当前 Host 对话是否拥有目标 Turn。
- 归属不一致或 Turn 不存在时，统一拒绝查询，而不是暴露历史操作内容。
- Workspace Relay 网关维护 Turn 与会话的关联，在向远端转发 Activity 查询前验证所有权，降低网关已升级但执行端仍为旧版本时的泄漏风险。
- 两个不同 Host 会话的真实 MCP 工具调用、同会话正常查询、Workspace bootstrap、远端 Relay 与进程输出都加入了回归测试。

本修复限制的是 **Activity 历史查询**，不改变既有 Workspace 文件读写、Git 或 Shell 执行权限。Host conversation scope 仍依赖 Host 提供的会话元数据；缺少稳定会话标识时沿用现有 MCP 请求或传输会话回退机制，不把 `turnId` 当成认证凭证。

相关问题：[GitHub #195](https://github.com/Akira-TL/forgerelay/issues/195)。

## 稳定性修复

- **进程轮询：** 非交互式 Bash 等待保持预期时间窗口，有界的零等待查询不能被用于高频轮询；保留交互输入、尺寸变更和中断所需的短等待行为。
- **远程等待：** Relay 超时策略与服务端进程等待策略保持一致，远端长等待请求留出适当的截止时间余量。
- **Shell 工作流指令：** 修复服务器指令提示中的保留问题。
- **Workspace Panel：** 在打开或复用 Workspace 后进一步提醒 Host 为当前工作轮次显式调用 `activity_panel`。不会隐式创建或自动打开 Panel。

## 升级与兼容

- 从 `1.3.1` 升级无需修改 Config System v2 配置，也不需要数据迁移。
- 不新增 MCP Core 工具，保持当前显式 `activity_panel` 生命周期。
- 已授权的同对话 Activity 查询保持有效；跨对话访问其他 Turn 的历史数据会被拒绝，这是有意的安全行为变化。
- 运行中的旧 ForgeRelay 实例不会因 GitHub 仓库更新而自动获得补丁，需要升级并重启该实例。Relay 场景建议网关与远端都升级。

## 验证与发布门槛

安全修复开发阶段已经完成双会话真实 MCP 入口测试、Relay 与 Composite 回归、类型检查、架构检查，以及完整 `npm test`。正式 `v1.3.2` 发行还必须对 **包含版本号及本文件的最终提交** 完成本地 release gate、打包与真实 Host 人工验收。

按照仓库发布规则，在开发者针对 exact release-ready HEAD **明确报告人工验收 PASS** 前，不创建或推送 `v1.3.2` tag。批准后才允许由 GitHub Release workflow 验证 Linux、macOS 和 Windows 并发布正式 npm 与 GitHub Release。
