# ForgeRelay 1.3.0

ForgeRelay 1.3.0 重整了人类 CLI 的长期边界，并把 Agent context source 正式纳入 Config System v2。这个版本不改变 ForgeRelay 的 canonical MCP Core tool surface；重点是让“启动运行时、声明配置、连接外部运行时、系统诊断”各自拥有稳定入口，同时让不同 Agent 生态可以复用自己的 instructions / Skills 布局，而不需要 ForgeRelay 再维护一套私有 Agent Skill namespace。

## CLI 架构

公共顶层命令收敛为：

- `forgerelay serve` — 启动 ForgeRelay runtime；
- `forgerelay init` — 首次设置与 setup-owned 配置；
- `forgerelay config` — 声明式配置读取、修改与 provenance；
- `forgerelay connect` — Remote ForgeRelay 与 External MCP 的运行时连接关系；
- `forgerelay system` — ForgeRelay 自身诊断、状态与维护。

裸 `forgerelay` 现在只显示帮助，不再隐式启动服务器。这是本版本最需要注意的 CLI 行为变化：现有脚本、systemd/service wrapper 或手工启动命令必须显式改为 `forgerelay serve`。

旧的 `start`、`hooks`、`auth`、`mcp`、`maintenance` 与 `agents` 入口在兼容窗口内继续存在，但不再出现在新的公共 help 中，也不再定义长期 CLI 架构。

## Runtime overrides

`forgerelay serve` 支持仅当前进程生效的 host、port、allowed roots 与 client-facing public URL override，以及既有 elevated-startup 显式 opt-in。

这些参数：

- 优先于环境变量与持久配置；
- 不会写回 `config.json`；
- multi-value roots / public URLs 使用本次 CLI 显式集合，而不是偷偷追加 lower-priority persisted values。

这使 7677/7678、多实例调试与临时网络拓扑不再需要先修改持久配置。

## Config CLI

`forgerelay config` 现在使用一致的 domain-first contract：

- General Config 直接使用 `config get/set/unset/check/sources/explain`；
- Agent Context 使用 `config context ...`；
- External MCP definitions 使用 `config mcp ...`；
- Lifecycle Hooks 使用 `config hooks ...`；
- Language Servers 使用 `config lsp ...`；
- Subagent Profiles 使用 `config subagents ...`。

named-resource domain 在适用时额外提供 `remove <name>`。所有 domain adapter 继续写各自 canonical Config v2 storage，而不是被压进一个通用 JSON 文件。

读取默认返回 effective resolved view；Project / Project Local / User / runtime / built-in precedence 仍由 Config System v2 resolver 统一负责。写入默认目标是当前 Project shared config，`--project <path>` 明确选择其他 Project，`--global` 写 machine-level 配置；不会在 Project 解析失败时静默退回 global。

## Agent context sources

Agent context source 现在有三个正式 Config v2 字段：

```text
systemInstructionsPath
instructionNames
skillPaths
```

built-in defaults 为：

```text
systemInstructionsPath = ~/.agents/AGENTS.md
instructionNames        = [AGENTS.md]
skillPaths              = [~/.agents/skills, ./.agents/skills]
```

显式配置采用 replace semantics，并支持正常的 Config v2 precedence 与 provenance inspection。Project-relative Skill paths 继续相对 Workspace/project root 解析；ForgeRelay 不识别或特殊适配 Claude、Codex、Pi、OpenCode 等 provider-specific 目录。

ForgeRelay 不再把 `~/.forgerelay/skills` 或 Project `.forgerelay/skills` 作为隐式 Agent Skill 默认来源。ForgeRelay 自己的产品指导继续通过 Capability Guides、workflow instructions 与 shell instructions 表达。

Workspace 在 effective context-source 配置变化后会刷新 instruction / Skill context fingerprint；已经移除的 Skill 不会继续从旧缓存可读，新 Skill 仍保持 metadata-first / 按需读取语义。

## Connect 与 System

Remote ForgeRelay 的 setup/auth/runtime 管理现在以 `connect relay` 为 canonical 人类入口；External MCP 的 status、test、OAuth authentication 与 logout 归入 `connect mcp`。External MCP definition 本身仍属于 `config mcp`，credentials 继续留在 machine-private auth storage。

`system doctor`、`system status`、`system inspect` 与 `system prune` 收拢 ForgeRelay 自身诊断与维护；既有 runtime lease、retention 与 destructive-maintenance 保护保持不变。

## Legacy Config compatibility

v1.3.0 不删除 v1.2 仍支持的 ForgeRelay-owned legacy Config source。它们继续可读并通过统一 resolver 进入 effective view。

本版本按既有兼容计划加强 deprecation diagnostic：如果一个 legacy field/source 已声明 removal version，warning 现在会明确显示它将在 **ForgeRelay 1.4.0** 被移除，并同时给出 canonical replacement。

建议在升级后使用：

```bash
forgerelay config check --global
forgerelay config sources --global
forgerelay config migrate --dry-run --global
```

或对具体 Project 使用 `--project <path>`，在 v1.4.0 前完成显式迁移。

## Debug 修复

交互式 debug server 在 `publicBaseUrl` 带 path prefix 时，现在会打印真实 mounted health endpoint。例如部署前缀为 `/forgerelay/debug` 时显示：

```text
http://127.0.0.1:7677/forgerelay/debug/healthz
```

而不是错误的 root `/healthz`。
