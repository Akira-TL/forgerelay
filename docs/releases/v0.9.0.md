# ForgeRelay 0.9.0

ForgeRelay 0.9.0 starts the Workspace Recovery & History line with a read-only recovery diagnostic model for managed worktrees. It makes externally damaged worktree backing inspectable before any repair capability is introduced.

## Highlights

- **Managed-worktree recovery diagnostics:** `open_workspace` inventory and inspection now report a bounded recovery projection for active managed worktrees, distinguishing healthy, recoverable, and manual-intervention states.
- **Concrete failure observations:** diagnostics can identify missing backing, stale or missing Git worktree registration, missing managed/target branches, branch mismatch, and missing or unavailable source repositories.
- **Read-only by design:** inventory and inspection do not prune worktrees, recreate backing, alter refs, refresh Workspace usage merely because it was inspected, or otherwise repair Git state.
- **Relay-safe projection:** relayed Workspace inspection carries the same bounded facts from the Execution ForgeRelay while preserving the Gateway Workspace identity and stripping unknown remote fields.

## Contract alignment

- The Roadmap and product documentation now reflect that first-class `subagent.session` delegation and Hook-backed managed-worktree close verification are already shipped.
- Managed TypeScript/JavaScript and Pyright installation is documented as explicitly user-authorized, disabled by default, and dynamically usable after installation without a ForgeRelay restart.
- The canonical nine Core MCP tools remain unchanged; recovery mutation is intentionally deferred to a later 0.9.x Capability release.

## Compatibility and safety

0.9.0 adds observation only. It does not automatically repair or clean managed worktrees, and it does not guess when Git identity or branch ownership cannot be proven. Existing Workspace identities and close/reopen behavior remain unchanged.
