# Native File Download

ForgeRelay can save a file attached to or generated by an MCP host directly into
an already-open workspace.

Enable the capability with:

```bash
FORGERELAY_ARTIFACTS=1 forgerelay serve
```

Use the canonical `FORGERELAY_ARTIFACTS` variable; the old
`DEVSPACE_ARTIFACTS` name is no longer read.

## Workflow

1. Open the destination project with `open_workspace`.
2. Call the `capability` Gateway with `name="artifact.download"`, `action="run"`,
   the existing `workspaceId`, the native file value in the Gateway's top-level
   `file` slot, and a workspace-relative destination in `arguments.path`.
3. Use the returned normalized path with ordinary ForgeRelay file tools.

The capability creates missing parent directories and refuses to overwrite an existing
destination.

## Input boundary

The `file` input must be the native value supplied by the MCP connector. Do not
replace it with:

- an arbitrary URL string;
- a local host path guessed by the model;
- base64 content;
- embedded credentials;
- an expanded object containing unsupported fields.

Signed URLs/native connector objects should not be copied into shell commands or
logs.

## Limits

Downloads are streamed under the configured maximum:

```text
FORGERELAY_ARTIFACT_MAX_FILE_BYTES
```

The default is 100 MiB (`104857600`). Partial temporary files use a private
ForgeRelay prefix and are published without overwrite after successful transfer.

The secure native-file publication implementation is currently exposed on Linux
where the required descriptor-anchored filesystem path is available.

## Non-goals

There is currently no:

- artifact quota or artifact-root database;
- TTL/pinning system;
- automatic background artifact cleanup service;
- arbitrary URL download mode;
- conflict/overwrite mode.

Use normal workspace tools for explicit inspection, replacement, movement,
renaming, or deletion after the file is present.
