# 通过安全外壳（SSH）引导实例信任并复用模型上下文协议（MCP）入口

锻造中继（ForgeRelay）之间的长期认证采用独立于宿主开放授权（OAuth）的实例信任（Forge Trust）。用户通过命令行（CLI）调用本机安全外壳（SSH）客户端完成引导；安全外壳目标（SSH target）、安全外壳别名（SSH alias）、跳板链和密钥选择继续由安全外壳自身解析，锻造中继不复制一套连接配置。发起实例生成高熵信任令牌，只把令牌哈希写入执行实例，本地保存可出站使用的令牌；每条信任关系都是有方向的并可独立轮换或撤销。实例间实际工作通信继续复用现有模型上下文协议（MCP）服务入口，由认证结果区分宿主身份和受信实例身份；只有受信实例身份可以携带锻造中继内部的可信上游会话信息。

用户建立信任时可以显式指定锻造中继别名（Forge alias），例如 `forgerelay auth user@host --alias workstation`。若安全外壳目标本身就是适合作为名称的安全外壳别名且未传入 `--alias`，则默认复用该名称；若目标是明显的网络地址而未提供别名，交互模式应提示用户命名，非交互模式应要求显式提供别名。锻造中继别名只在本地信任表中稳定标识远端实例，模型在工作区接力时只使用这个别名，不接触安全外壳目标、跳板链、网络地址或认证材料。

认证命令应尽量保持安全外壳（SSH）的使用习惯。安全外壳配置文件中已经存在的用户名、端口、身份文件、代理和跳板设置无需再次传入；需要临时覆盖时，首版至少支持与安全外壳一致的 `-J`、`-p`、`-i`、`-F` 和可重复的 `-o`。其中 `-J jump1,jump2` 允许多级安全外壳跳板（SSH ProxyJump），各跳板本身也可以是安全外壳别名。多级安全外壳跳板只用于到达最终执行实例，不改变工作区接力首版仍然只允许“发起实例到执行实例”单跳的协议约束。

认证引导通过固定的远端锻造中继命令和标准输入传递请求，不把信任令牌或令牌哈希拼进远端命令行参数。认证成功后，本地记录远端稳定实例标识、安全外壳目标、显式安全外壳参数、锻造中继别名、工作地址和出站令牌；远端只记录来源实例标识和令牌哈希。重复认证同一个远端实例用于轮换令牌，不因目标字符串变化创建重复身份；别名可以独立重命名，别名冲突必须显式失败而不能静默覆盖其他实例。

工作区不属于认证配置。用户先建立机器级实例信任，之后模型通过 `open_workspace` 的远端目标参数选择一个锻造中继别名，并传递应在执行实例上解释的工作区路径。执行实例继续独立执行允许根目录与符号链接边界检查；发起实例不能把本地同名路径当成远端路径，也不能在远端不可用时静默回退。

## 未采用方案

- 不让模型提供实例地址、端口、安全外壳参数、认证头或令牌，避免模型把锻造中继变成任意网络访问入口。
- 不复制安全外壳（SSH）的主机、跳板、密钥和代理配置语义；现有安全外壳配置仍是认证引导阶段的连接事实来源。
- 不要求实例之间执行浏览器式开放授权（OAuth）流程，因为机器间长期连接不应依赖人工重定向和授权页面。
- 不单独增加接力专用模型上下文协议（MCP）端点；认证主体已经足以区分普通宿主请求与受信实例请求。
- 不把工作区路径、允许根目录或工作区收藏绑定到实例信任记录；实例信任解决机器身份，工作区接力解决执行位置。
