# 分离宿主开放授权（OAuth）与命令行（CLI）远端认证

锻造中继（ForgeRelay）保留聊天宿主（ChatGPT）需要的开放授权（OAuth）网页流程，同时增加独立的命令行认证路由（CLI Authentication Route）。命令行远端认证不经过网页，而是以现有所有者令牌（owner token）换取现有访问令牌与刷新令牌；直接连接时所有者令牌可由 `--token` 显式提供或在交互终端隐藏输入。若安全外壳链（SSH route）存在且用户指定 `--ssh-auth`，最终目标机上的固定锻造中继（ForgeRelay）子命令只读取该机所有者令牌并通过安全外壳（SSH）标准输出返回发起进程；发起进程随后仍经已经建立的服务连接调用与直连完全相同的命令行认证路由。这样安全外壳路径和直连路径只在所有者令牌来源上不同，认证请求、令牌签发和后续模型上下文协议（MCP）客户端完全复用。远端所有者令牌只允许短暂存在于发起进程内存中，不得进入命令行参数、日志、活动审计或持久化远端记录。

`forgerelay auth` 只要求一个远端服务目标（Remote Service Target），并根据是否存在 `-J` 自动选择连接方式。没有 `-J` 时直接从本机访问该目标；存在 `-J` 时，`-J` 表示完整安全外壳链（SSH route），最后一个节点是最终安全外壳目标，之前的节点按照安全外壳跳板（ProxyJump）顺序使用。锻造中继调用系统安全外壳（SSH）把最终目标机器视角下的远端服务目标映射到本机随机高位回环端口，然后继续使用与直连完全相同的命令行认证和模型上下文协议客户端。连接方式由参数确定，不进行“直连失败后自动改走安全外壳”的网络探测。

`forgerelay auth` 同时完成认证与远端实例登记。持久化记录保存锻造中继别名（Forge alias）、远端稳定实例标识、远端服务目标、访问令牌、刷新令牌以及可选安全外壳链；随机本机端口、安全外壳进程和临时映射地址只属于运行时连接状态。工作区只通过锻造中继别名选择远端，后续路由以稳定实例标识和远端工作区标识为准。

## 未采用方案

- 不为直连和安全外壳（SSH）分别设计两套远端地址参数或两套认证流程。
- 不把安全外壳（SSH）设为远端访问的必选依赖。
- 不自行实现跳板协议；只把 `-J` 的链式输入转换为系统安全外壳已有的连接、跳板和端口转发能力。
- 不在直连失败后静默尝试安全外壳（SSH），避免认证凭据进入用户未明确选择的网络路径。
- 不要求已经具备安全外壳（SSH）登录权限的用户再次手工复制远端所有者令牌；`--ssh-auth` 只允许在显式安全外壳链下启用，并允许通过加密的安全外壳通道把所有者令牌直接交给发起进程用于一次认证请求，但不得持久化该令牌。
- 不维护实例信任令牌、双认证域、接力专用模型上下文协议端点或第二套网络服务。
