# 分离宿主开放授权（OAuth）与命令行（CLI）远端认证

锻造中继（ForgeRelay）保留现有聊天宿主（ChatGPT）需要的开放授权（OAuth）网页流程，同时增加独立的命令行认证路由（CLI Authentication Route）。命令行远端认证不经过网页：用户执行 `forgerelay auth <安全外壳目标>` 后，本机通过安全外壳（SSH）证明自己能够控制远端机器，并由远端固定命令签发一个短期、一次性认证凭据；本机随后把远端现有服务端口映射到随机本机高位端口，通过该映射调用命令行认证路由，以一次性凭据换取正常的访问令牌和刷新令牌。命令行认证与宿主开放授权最终共用同一令牌存储、同一承载令牌校验和同一个模型上下文协议（MCP）入口，因此不需要实例信任令牌、独立接力端点、第二套模型上下文协议服务或专门的机器认证数据库。

`forgerelay auth` 同时完成远端认证和远端实例登记。认证成功后，本机保存锻造中继别名（Forge alias）、安全外壳目标（SSH target）、必要的显式安全外壳参数、远端稳定实例标识以及命令行认证取得的令牌；不存在单独的 `add` 步骤。后续访问远端工作区时，本机按需选择一个随机高位端口，通过安全外壳端口转发（SSH Port Forwarding）映射到远端锻造中继现有服务端口，再用已保存的访问令牌访问普通模型上下文协议（MCP）入口。随机本机端口只属于当前隧道生命周期，不进入持久化远端实例身份。

安全外壳（SSH）继续完整负责用户名、密钥、主机别名、端口、代理和多级跳板（ProxyJump）。锻造中继不复制这些能力，也不让中间跳板机运行锻造中继。远端固定命令签发的一次性认证凭据必须高熵、短期、单次消费且不得写入日志；命令行认证路由即使经公开代理可达，没有通过安全外壳取得的一次性凭据也不能签发访问令牌。聊天宿主的开放授权网页路由保持现有行为，不因命令行认证而自动批准或绕过用户确认。

## 未采用方案

- 不再维护实例信任（Forge Trust）令牌、入站令牌哈希、令牌轮换和双认证域，因为安全外壳已经提供机器控制权证明，而命令行认证可以直接换取现有访问令牌。
- 不新增接力专用模型上下文协议（MCP）入口、统一域套接字或第二个网络服务；命令行认证路由与普通模型上下文协议入口继续使用现有锻造中继服务端口。
- 不仅依赖请求来自回环地址来判断命令行认证可信，因为公开代理或本机其他进程也可能到达同一服务；必须校验通过安全外壳取得的一次性认证凭据。
- 不让命令行（CLI）模拟聊天宿主的开放授权网页流程；命令行使用独立认证路由，聊天宿主继续使用标准开放授权（OAuth）兼容流程。
