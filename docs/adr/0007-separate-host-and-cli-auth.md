# 分离宿主开放授权（OAuth）与命令行（CLI）远端认证

锻造中继（ForgeRelay）保留现有聊天宿主（ChatGPT）需要的开放授权（OAuth）网页流程，同时增加独立的命令行认证路由（CLI Authentication Route）。命令行远端认证不经过网页：本机优先直接访问远端服务地址（Remote Service URL），在终端中以隐藏输入方式提交现有所有者令牌（owner token），由命令行认证路由换取正常的访问令牌和刷新令牌。命令行认证与宿主开放授权最终共用同一令牌存储、同一承载令牌校验和同一个模型上下文协议（MCP）入口，因此不需要实例信任令牌、独立接力端点、第二套模型上下文协议服务或专门的机器认证数据库。

`forgerelay auth` 同时完成远端认证和远端实例登记。直接能够访问远端服务时，不启动安全外壳（SSH），认证和后续模型上下文协议请求都直接访问远端服务地址。只有远端服务无法直接访问时，用户才额外指定一个安全外壳目标（SSH target）；本机通过系统安全外壳客户端建立临时本机回环端口到远端服务的端口转发，然后仍然调用完全相同的命令行认证路由和模型上下文协议入口。随机本机高位端口只属于当前安全外壳隧道生命周期，不进入持久化远端实例身份。

安全外壳（SSH）在该架构中只是可选传输层，不承担锻造中继自己的认证语义。主机别名、密钥、代理和多级跳板（ProxyJump）全部由用户已有安全外壳配置负责；锻造中继不增加单独的跳板配置、跳板协议或中间锻造中继节点。直连和安全外壳转发两种路径最终都得到一个可访问的远端服务地址，并复用同一远端客户端实现。

所有者令牌只用于命令行首次换取访问令牌，不用于后续普通模型上下文协议调用。非回环直连如果不能提供可信传输，不应发送所有者令牌；明文超文本传输协议（HTTP）不能因为目标是私有互联网协议地址（IP）就被视为安全。聊天宿主的开放授权网页路由保持现有行为，不因命令行认证而自动批准或绕过用户确认。

## 未采用方案

- 不把安全外壳（SSH）设为远端锻造中继的必选依赖；能够直接访问服务地址时优先直连。
- 不再通过安全外壳签发一次性认证凭据；命令行认证直接复用现有所有者令牌，并换取现有访问令牌和刷新令牌。
- 不维护实例信任（Forge Trust）令牌、入站令牌哈希、令牌轮换和双认证域。
- 不新增接力专用模型上下文协议（MCP）入口、统一域套接字或第二个网络服务。
- 不自行实现跳板能力；需要跳板时只调用系统安全外壳（SSH）并复用用户已有多级跳板（ProxyJump）配置。
- 不让命令行（CLI）模拟聊天宿主的开放授权网页流程；命令行使用独立认证路由，聊天宿主继续使用标准开放授权（OAuth）兼容流程。
